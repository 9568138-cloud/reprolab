## 一、意图控制策略：如何让 AI 的输出可被机器校验

### 1.1 问题

让大模型自由写代码并执行，会同时牺牲可复现性（每次结果不同）、安全性（沙箱逃逸面）和可评审性（评委看不懂生成逻辑）。

### 1.2 我们的做法：把 AI 的输出压缩到「计划 DSL」

AI 只被允许输出一个固定结构的 JSON：

```json
{ "version": 1, "question": "...", "steps": [
  { "id": "s1", "op": "describe", "params": { "column": "resistance_kohm" } },
  { "id": "s2", "op": "drop_outliers", "params": { "column": "resistance_kohm", "k": 1.5, "confirm": true } }
] }
```

- **算子白名单 12 个**：`describe / drop_outliers / transform_log / correlate / fit_linear / scatter / group_summary / ttest / normalize / trend / histogram / missing_report`；
- 越界即 `validatePlan` 抛错（有单测覆盖）；
- 参数类型、列名存在性、步数上限（12）全部机器校验；
- **破坏性算子（删数据）必须带 `confirm: true`**，且前端还会再拦一道：不勾选「我确认」执行按钮保持 disabled。

### 1.3 三层降级，保证永远能演示

| 场景 | 行为 |
| :-- | :-- |
| 配了 API Key，模型正常 | LLM 编译 → 通过校验 → 执行 |
| LLM 返回非法 DSL | 校验失败 → 自动降级为本地规则编译（同样可复现） |
| 完全离线、无 Key | 规则编译（关键词 → 算子映射） |

### 1.4 上下文控制

- 给模型的是**结构化列信息**（列名 + 类型 + 行数），不是原始数据 → 上下文短、隐私风险低；
- `temperature: 0`、要求只输出 JSON、`response_format: json_object`；
- 模型的输出永远不直接进入执行层，必须过校验器。

## 二、架构设计：AI 生成的代码如何被约束

### 2.1 分层

```
UI（index.html + src/ui/app.js）
  ↓
计划层（src/planner.js：编译 / 结论卡 / 引用校验）
  ↓
内核层（src/kernel：csv → ops → index 执行器 → hash）
  ↓
导出层（src/export：zip + 复现包）
```

**约束手段**：层与层之间只有纯函数与结构化的对象流转；内核层不依赖 DOM，因此可以在 Node 里直接跑单测（24 条）；导出层不依赖内核内部状态，只接受 `(plan, run)` 快照。

### 2.2 关键取舍

| 取舍 | 选择 | 理由 |
| :-- | :-- | :-- |
| 框架 | 不上 React/Vite，原生 ES module | 3 天工期下「可复现」优先：零依赖、断网可跑、没有构建产物与环境漂移 |
| 执行位置 | 浏览器内 | 没有服务端执行用户代码 → 无边执行漏洞；数据不出本机 |
| 数值实现 | 自研 ~200 行统计内核 | 去掉 numpy/scipy 依赖，浏览器与 Node 结果一致，便于逐位复现 |
| ZIP | 手写 store 模式写入器 | 不引第三方包，导出包在任何解压工具都能打开 |

### 2.3 哈希链

- 原始数据：CSV 文本 SHA-256；
- 每一步：`inputHash`（行数、列、已剔除行、已变换的稳定序列化）→ `outputHash`（该步输出）；
- 产物：`artifactHash` = SHA-256(稳定序列化的 plan + outputs + droppedRows)；
- 稳定序列化保证键序无关 → 同一语义一定得到同一哈希。

## 三、可复现性论证

### 3.1 论证结构

1. **输入可固定**：数据以只读方式载入并记录哈希；计划是显式 JSON，可导出可粘贴；
2. **过程可固定**：没有随机数、没有时间依赖、没有并发；算子实现是纯函数；
3. **输出可验证**：「重跑一致性校验」对同一 `(data, plan)` 重算并比较产物总哈希，界面直接给出 ✅/❌；
4. **可第三方验证**：复现包里有 `data.csv / plan.json / run.json / report.md / meta.json`，报告写明每步哈希与最终哈希；
5. **可离线自证**：包内自带 `verify.mjs`，不需要 ReproLab、不需要联网，`node verify.mjs` 会重算数据哈希、用 `plan.json + run.json` 重建产物指纹并比对、检查算子白名单与 `confirm` 标记。改掉 `run.json` 里任何一个数字都会 FAIL（实测退出码 1）。

### 3.2 实测证据（10 月 27 日）

- 同一数据 + 同一计划执行两次：产物哈希逐位一致（界面「重跑一致性校验」直接给出两次哈希比对）；
- 真实数据 iris（R 内置鸢尾花数据集，150 行）：点选「分组汇总 + 两组比较」生成 3 步计划，产物哈希逐位可重算；setosa 与 versicolor 的花瓣长均值差 -2.798 cm，p < 0.0001；
- airquality（纽约空气质量，153 行）：Ozone 列有 37 个缺失（24.2%），缺失盘点如实报告，相关性样本自动降到 116 行；
- faithful（老忠实泉，272 行）：喷发时长与等待时间 r = 0.9008，直方图 272 个样本全部落箱；
- 24 条单测覆盖：CSV 解析、缺失标记归一（NA/空串）、白名单拒绝、破坏性算子确认、可复现、异常点、相关性、分组汇总、Welch t、缺失盘点、时间趋势、直方图、删除清单一致性、空单元格不当 0 的回归、结论引用缺失报错、复现包指纹可重算、审计三态。

### 3.3 已知边界

- 浮点运算在相同 IEEE754 环境下一致；跨 CPU 架构的极端差异未验证；
- LLM 编译出的计划若措辞不同，计划本身可能不同（但一旦确定计划，执行仍逐位一致）——所以「同一计划」是复现的前提，这也正是我们把计划导出的原因。
