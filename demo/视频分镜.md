# 演示视频分镜（5–8 分钟 · 含 ≥2 分钟 AI 协同复现）

> 官方要求：5–8 分钟；**至少 2 分钟展示 AI 协同复现过程**；链接须公开可访问（B 站 / 抖音）。
> 目标：让评委在 90 秒内看懂「点选/一句话 → 可审阅计划 → 每步留痕 → 逐位复现」，再用 2 分钟看懂「AI 怎么被约束、怎么迭代」。

---

## 一、录制前 5 分钟准备

| 项 | 做法 |
| :-- | :-- |
| 数据 | 提前把 `sample-data/中国70城房价指数_环比.csv` 和 `tests/fixtures/audit-case.json` 放在桌面，方便拖拽 |
| 窗口 | 浏览器全屏 1920×1080，缩放 125%；关掉所有通知（微信/QQ/邮件） |
| 终端 | 单独一个窗口，字体 18px，只留 `reprolab` 目录 |
| 隐私 | 桌面不放私人文件；终端路径不要出现个人信息；录制里不要出现 API Key |
| 预跑 | 手动走一遍：拖 CSV → 点选两组比较 → 生成计划 → 执行 → 重跑校验 → 导出包 → `node verify.mjs` |
| 录屏 | OBS / Win+G，只录浏览器 + 终端；1080p / 30fps |

## 二、分镜表

### 第 1 段｜痛点与定位（0:00–0:45）

| 画面 | 操作 | 口播要点 |
| :-- | :-- | :-- |
| 首屏 | 停留 2 秒，鼠标划过标题 | 「做实验、写报告的人都遇到过：结论和数据对不上，别人复现不出来。」 |
| 首屏 | 滚到数据接入 | 「ReproLab 把一次分析变成可审阅的计划；反过来，也能拿它去审别人的报告。」 |

### 第 2 段｜完整闭环（0:45–2:15）

| 画面 | 操作 | 口播要点 |
| :-- | :-- | :-- |
| 数据接入 | 拖入 `中国70城房价指数_环比.csv` | 「国家统计局的 70 城房价指数，1.68 万行，中文列名。」 |
| 02 点选 | 点「分组汇总」「相关性」，分组列选「城市」 | 「我不写代码，也不写 SQL：勾两个意图、选一列分组，计划就出来了。」 |
| 03 计划卡 | 停留 | 「这就是全部：3 步、每步一个白名单算子，参数看得见。」 |
| 展开「查看计划 DSL」 | 展开再收起 | 「AI 的产出最多到这个结构，越界直接拒绝执行。」 |
| 执行 | 点执行 | 「执行在浏览器内，数据不出本机。」 |
| 04 结论卡 | 鼠标停在 `r = 0.6234`、`深圳 100.44` | 「这些数字绑在计算步骤的输出字段上；字段不存在，页面直接拒绝渲染。」 |

### 第 3 段｜溯源与图（2:15–3:00）

| 画面 | 操作 | 口播要点 |
| :-- | :-- | :-- |
| 点徽章 | 点 `diff` 徽章 | 「点一下，跳到算出它的那一步。」 |
| 柱状图 | 停留 3 秒 | 「70 个城市的二手住宅指数均值，只画前 12 组，标题写清共 70 组。」 |

### 第 4 段｜复现（3:00–3:40）

| 画面 | 操作 | 口播要点 |
| :-- | :-- | :-- |
| 重跑校验 | 点「重跑一致性校验」 | 「同一数据 + 同一计划，重跑两次产物哈希逐位相同。」 |
| 导出 | 点「导出复现包」 | 「包里有数据、计划、执行记录、报告，还有一份自带校验脚本。」 |
| 切终端 | `cd 下载目录 && unzip -o reprolab-*.zip -d check && cd check && node verify.mjs` | 「评委不用打开 ReproLab，一条命令就能验。」 |
| 终端（加戏） | 改 `run.json` 一个数字 → `node verify.mjs` | 「改任何一个数字，它立刻 FAIL，退出码 1。」 |

### 第 5 段｜审计：把"可复现"变成"我替你验"（3:40–4:50）

| 画面 | 操作 | 口播要点 |
| :-- | :-- | :-- |
| 切到「审计」 | 点顶栏审计 | 「同一个内核，反过来用：给我一份别人的报告，我逐条重算。」 |
| 导入审计案 | 选 `tests/fixtures/audit-case.json` | 「这是别人写的 5 条结论。」 |
| 点开始审计 | 结果表 | 「3 条通过、1 条不符——报告写 71 个城市，数据里只有 70 个；还有 1 条引用了不存在的步骤，判为无法复现。」 |
| 停留 | 指着「不符」那行 | 「它不会说'大概不对'，它告诉你差在哪一列、哪个字段。」 |

### 第 6 段｜AI 协同复现（4:50–7:20，**≥2 分钟**）

这一段是评分重点：不是演「AI 帮我写代码」，而是演「我怎么约束它、怎么发现它错、怎么改回来」。

| 画面 | 操作 | 口播要点 |
| :-- | :-- | :-- |
| 全屏 `prompts/screenshots/` 四张会话截图 | 一张张过 | 「需求、方案、建仓这三段发生在 CherryStudio，AI 给的是作战手册，我按它执行——原始会话，没改过。」 |
| `prompts/README.md` | 滚到 iter-01 | 「代码迭代有 11 轮，每轮一个 commit：AI 产出、我发现了什么问题、怎么改的。」 |
| 讲 iter-01 的 bug | 高亮那段 | 「第一版解析器把注释行当表头，测试直接挂。我没让它自己修，而是先把约束写清楚。」 |
| 讲 iter-11 的 bug | 高亮「632 mAh」那段 | 「扩算子时 B 组均值少了 600——因为空单元格被当成了 0。是'632'这个明显不合理的数字把它揪出来的，修完补了回归测试。」 |
| `tests/kernel.test.mjs` | 滚到那条回归测试 | 「现在 24 条测试是这条链的护栏。」 |
| `src/kernel/index.js` 的 `canonicalArtifact` | 高亮 | 「复现口径只有一处实现：界面重跑、导出包、第三方校验都调它。」 |

### 第 7 段｜边界与收尾（7:20–7:50）

| 画面 | 操作 | 口播要点 |
| :-- | :-- | :-- |
| README「已知边界」 | 停留 | 「我不吹它能做一切：5 万行以内、12 个算子、单文件单用户；跨 CPU 浮点差异没验证。」 |
| 回首页定格 | 慢滚 | 「溯真 ReproLab：结论有出处，过程可复现。」 |
