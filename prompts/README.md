## iter-10 · 审计模式：从「我证明」到「我替你验」（对应 commit [iter 10]）

- 我做的判断：市面上的"AI 数据分析"太多了，再往下做只是更长的功能列表。真正没人做的是**替别人验报告**——这正好是我们"结论绑字段 + 哈希可重算"的能力反过来用。
- 指令：
  > 加审计模式：输入一份别人的报告条目（JSON：text/stepId/field/value），用同一份数据重算，逐条判定 通过 / 不符 / 无法复现；能导出 Markdown 审计报告。
- AI 产出：`src/audit.js`（auditReport / compareValue / auditToMarkdown）、`index.html` 顶栏双模式、`src/ui/app.js` 审计交互与结果表、`sample-data/audit-case.json`（6 条结论，1 条被改、1 条引用不存在的步骤）、4 条测试
- 判定口径：数值允许 0.1% 相对误差（报告通常四舍五入到 4 位）；超出即"不符"；步骤或字段缺失即"无法复现"
- 结果：commit `[iter 10]`，19 → 24 条单测（含审计 4 条）

## iter-11 · 能力面从 6 个算子扩到 12 个（对应 commit [iter 11]）

- 我做的判断：评委觉得"简陋"，十有八九是"能点的功能太少"。分析再严谨，只有 6 个算子还是会被问"能比较两组吗""能看分布吗"。先扩能力，不动内核结构。
- 指令：
  > 加六个算子：分组汇总、Welch 两组 t 检验、z-score 标准化、按行序的时间趋势、分布直方图、缺失值盘点。每个都要能被规则编译命中、能出结论卡、能被审计引用。
- AI 产出：`src/kernel/stats.js`（meanStd / welchTTest / histogram）、`src/kernel/ops.js`（6 个新算子 + 分组取值）、`src/planner.js`（关键词映射、步骤编排、4 条新结论卡）、`sample-data/battery.csv`（两组电芯，含 4 处缺失）
- **踩到的坑（写进技术文档了）**：B 组有 4 个空单元格，原来的分组取值用 `Number(cell)`，空串变成 `0`，把 B 组均值从 2932 拉到 2345，t 检验均值差算成 632 mAh。是"两组均值差 632"这个明显不合理的数字暴露了它。修完补了回归测试：**空单元格必须算缺失，不能算 0**。
- 结果：commit `[iter 11]`，24 条单测全绿

## iter-13 · 点选式提需求：不用猜列名（对应 commit [iter 13]）

- 我发现的问题：写完"一句话"清单才发现，规则编译**不认中文列名**——问「内阻随循环次数变化」，它把主列当成 capacity_mah 算了一遍，因为 `温度`、`内阻` 这些词跟 `temp_c`、`internal_mohm` 对不上，列其实是按顺序猜的。演示时评委随便说一句就会踩到。

- 我做的判断：点选模式的价值不是"更好用"，是**把不确定性从演示里删掉**——没有 AI、没有关键词、没有猜列，生成的计划仍然过白名单、仍然可复现、仍然能审计。

## iter-15 · 加中文数据（对应 commit [iter 15]）

- 用户的要求：**找中文数据**——示例数据全是 iris / faithful 这类英文列名，评审看着隔一层。

- 做了什么：从公开镜像仓库取国家统计局「70 个大中城市商品住宅销售价格指数」，整理成 4 个中文 CSV（环比 / 同比 / 定基比 / 2025-12 横截面），列名全中文：日期、城市、新建商品住宅指数、二手住宅指数。

- 顺带修的两处：
  - 分组列默认值改成「不同取值最少的文本列」——原来取第一列，日期会被当成分组列；

- 实测：16,800 行加载 + 3 步执行共 34ms；新建 vs 二手住宅指数 r = 0.6234（n = 16800）；按城市分组 70 组，均值最高的是深圳（100.44）。

- 结果：commit `[iter 15]`，24 条单测仍全绿

## iter-24 · 加第 13 个算子：条件筛选（对应 commit [iter 24]）

- 缺口：用户想问「只看 30℃ 以上的数据」，但白名单里没有筛选算子，只能全量算。

- 做法：新算子 filter_rows(column, op, value)，op 支持 > >= < <= == !=；它和「剔除异常点」共用一套行排除机制（excludedRows），所以下游统计、图表、复现包口径自动一致。

- 踩到的坑：两张表叠加时行号错 1 —— detectOutliers 返回的是「掩码后数组下标 + 2」，我直接拿它当原始行号去查表，结果整体偏移 1。修法是先转回下标（r - 2）再查原始行号表，并补了回归测试（筛选 + 剔除叠加时，剔除行不能落在筛选已排除的行里）。

- 口径改造：canonicalArtifact(plan, steps, excludedRows) 统一用 excludedRows；复现包 run.json 同时记 excluded/dropped/filtered 三份清单；verify.mjs 重建指纹也跟着改。

- 实测：问「只看二手住宅指数大于 101 的数据，算一下相关性」→ filter_rows → describe → correlate，保留 1479 行；复现包跑 node verify.mjs 五项全 PASS（13 个算子内）。

- 结果：commit [iter 24]，34 条单测全绿
